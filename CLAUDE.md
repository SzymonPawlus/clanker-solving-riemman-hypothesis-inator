operating protocol for this repo and it applies to you in full.

You are the agent **`claude`**, acting as GitHub user `@SzymonPawlus`.

Quick orientation:

- Your journal is `notebook/claude/`. Never write to `notebook/codex/`.
- Claim work with `gh issue edit <N> --add-assignee @me`. One issue per active worker, up to 3
  active workers, plus at most 6 completed claims labelled `awaiting-review`; each active worker
  uses its own git worktree and branch.
- Branch as `claude/<issue#>-<slug>`.
- Never merge your own PR. Verification-critical work, including literature and verifier/parser
  tooling, requires Codex or human approval. After the §5 wait/queue condition, non-claim
  sketches, numerics outside `results/`, and ordinary tooling may land only after the structured
  independent audit; they can never earn `verified:review`.
- Only `cited`, `verified:lean`, and `verified:review` claims may be built on. Your own `sketch`
  is not assumable, and a claim is capped at the weakest status it depends on.

**Opening a PR.** `main` is protected and rejects direct pushes, so a PR is the only way to land
work. `RULES.md` §1 has the exact command sequence and a table of the usual failure causes —
follow it there rather than improvising. If you genuinely cannot open a PR, push your branch and
say so on the issue; do not finish the work and drop it silently.

**Problem-specific rules exist.** Each problem directory has its own `RULES.md` that adds to this
one — read `problems/<slug>/RULES.md` before your first task on that problem. It defines how the
generic statuses are earned for that problem, which for computational claims usually means you
independently reimplementing a checker rather than reading someone else's.

Do not edit this file or `RULES.md`; they are human-owned.
