1. The exact Oler window for k = 7 (n = 27)
==============================================================================
Oler (cited): n <= a^2/2 + 3a/2 + 1 for n points at separation 1 in an
equilateral triangle of side a.  So 27 points force a^2 + 3a - 52 >= 0.
Let a* be the positive root of a^2 + 3a - 52 = 0, i.e. a* = (-3 + sqrt(217))/2.
Then a*^2/2 + 3a*/2 + 1 = (a*^2 + 3a* + 2)/2 = (52 + 2)/2 = 27 exactly.
  exact bracket: 5.865459 < a* < 5.865460   (p(lo) = -1.372e-05, p(hi) = +1.012e-06, both exact)

So Oler alone already settles Erdos-Oler for k = 7 outside a window:
  27 unit-separated points cannot fit when a < a* = 5.86546...
  the whole open case is a in [a*, 6), a window of width < 0.135.
Status: `sketch` (elementary arithmetic on top of the `cited` Oler bound).

4. KC-2: hypothesis H fails at the extremal lattice itself
==============================================================================
H (refuted in ../oler-slack-analysis §4 by flat arcs):
    n <= (2/sqrt3) A(conv E) + b/2 + 1,   b = |E cap d conv(E)|.
The published refutation uses degenerate near-collinear sets, which invites the
repair 'H is presumably fine for fat, lattice-like configurations'.  It is not.

Witness: take the triangular lattice T(k) -- the extremal configuration for
Oler -- scale it by lam = 1 + delta, then push every boundary point strictly
inside by eps.  n and a are essentially unchanged; b collapses from 3(k-1) to 3.

lam = 101/100, eps = 1/1000  (exact rationals)

  k    n         a  b before  b after   min sep^2     H rhs  H holds  violation
  3    6    2.0200         6        3    1.016604    4.5367    False    +1.4633
  4   10    3.0300         9        3    1.016604    7.0852    False    +2.9148
  5   15    4.0400        12        3    1.016604   10.6538    False    +4.3462
  6   21    5.0500        15        3    1.016604   15.2425    False    +5.7575
  7   28    6.0600        18        3    1.016604   20.8513    False    +7.1487

Every row violates H, by a margin that grows with k, at
configurations that are exactly the ones Erdos-Oler is about.  Everything in
the table is exact: separations, containment, hull, area, and the comparison.
Status of the witnesses: `refuted` for H (again, and for a better reason).

KC-2 FIRED.  b is not stable under an eps-perturbation that changes neither n
nor a; so no bound on b, however sharp, can rescue a bound whose right-hand
side is increasing in b.

5. KC-3: no count-based boundary term can beat Oler where it matters
==============================================================================
Suppose some Phi makes  n <= (2/sqrt3) A(conv E) + Phi(b) + 1  true for every
unit-separated E.  Flat arcs force Phi from below; the lattice then shows the
resulting bound is weaker than Oler's own.

(a) lower bound on Phi from flat arcs (exact):
   m  n = b    min sep^2   (2/sqrt3)A   Phi(b) >=
   3      4   1.00000000     0.076980    2.923020
   5      6   1.00000000     0.057735    4.942265
   8      9   1.00000006     0.024249    7.975751
  12     13   1.00000000     0.008256   11.991744

The bound is  Phi(b) >= b - 1 - (2/sqrt3)A, and A -> 0 along the family, so
    Phi(b) >= b - 1  for every b >= 3.

(b) what that costs, at the lattice (exact; the lattice's perimeter is rational):
  k    n  b = M(P)  Oler term M/2+1  best count term b  count better?
  3    6         6           4.0000             6.0000          False
  4   10         9           5.5000             9.0000          False
  5   15        12           7.0000            12.0000          False
  6   21        15           8.5000            15.0000          False
  7   28        18          10.0000            18.0000          False
  8   36        21          11.5000            21.0000          False

The best possible count term is at least as strong as Oler's only when
M(P) >= 2b - 2.  On the lattice M(P) = b exactly, so for b > 2 the count bound
is strictly weaker -- and it gets worse as k grows.

KC-3 FIRED.  Every Phi(b) is dead.  Note the honest limit of this argument: it
is about Phi depending on b alone.  A term Phi(n, b) is not excluded here, but
it is also not a boundary count any more -- see the README §6.

6. The stable replacement: corner clearance, and what k = 7 would need
==============================================================================
Counts are unstable (section 4).  Clearances are not: they move continuously.

Lemma C (proved in the README, status `sketch`).  If every point of E is at
distance >= t_i from corner A_i of T (cuts disjoint), then
    n <= a^2/2 + 3a/2 + 1 - sum_i (t_i^2 + t_i)/2.

For k = 7 the needed gain at a -> 6 is exactly 1 (27 vs the Oler value 27 at
a = 6), so with a common clearance t one needs 3(t^2 + t)/2 >= 1, i.e.
    t >= t7 = (-3 + sqrt(33))/6,   since  36 t^2 + 36 t + 9 = 33  <=>  t^2 + t = 2/3.
  exact bracket: 0.457427 < t7 < 0.457428   (g(lo) = -2.063e-07, g(hi) = +1.709e-06, both exact)

And this is exactly why it does not close the case on its own: the lattice
T(7) has points AT the corners, t = 0, gain 0.  Lemma C is a real inequality
but it is vacuous on the only configurations that matter, unless it is paired
with a statement forcing small clearance to imply near-lattice structure --
which is approach O (Oler stability), not this attack.
