# packing-r4-dual — exact dual certificate for the Euler-localised scoring family

**This is optimality-side (lower-bound) work and it is a NEGATIVE result. It produces no
packing, claims no construction, and establishes no new bound. It proves that a family of
candidate bounds cannot beat one the repo already has.**

## The question

`attacks/r4-delaunay` **measured**, with a floating-point LP, that the Euler-localised Delaunay
scoring family collapses onto Oler's inequality: the LP returns exactly `d(16) = √129 − 3`, and
freeing the score pointwise changes nothing. Its README §5 names two gaps:

1. the LP is solved in floating point, so the conclusion is a hypothesis, not a bound;
2. the structural reason — a "collapse proposition" — was never written.

This directory closes both.

## The method

**LP duality.** To prove rigorously that a minimisation LP's optimum is at least some value, you
exhibit a **dual feasible point** whose objective equals it. That is a finite list of nonnegative
numbers satisfying finitely many linear inequalities — checkable exactly, with no solver trust.

The LP being certified is the one in `experiments/packing-r4-delaunay/lp.py`:

```
minimise    B(a) - 1 = c_A·(√3/4)a² + 3·c_L·a
subject to  c_A·A_K + c_L·M_K ≥ n_K − 1     for each library configuration K
            c_A, c_L ≥ 0
```

Its constraints are *necessary* conditions on any member of the family, so a lower bound on its
optimum is an upper bound on what the family can prove.

**The dual we exhibit.** Call a configuration *Oler-tight* if `(2/√3)A + M/2 = n − 1`, and define
its **slope** `s(K) = 4√3·A(K)/M(K)`. The side-`m` triangular lattice has slope `m`; the `P×Q`
lattice rhombus has slope `3PQ/(P+Q)`; both are Oler-tight, exactly. Given two Oler-tight
configurations whose slopes bracket `a` (`s₁ ≤ a ≤ s₂`), set

```
λ  = (s₂ − a)/(s₂ − s₁)          y₁ = 3aλ/M₁          y₂ = 3a(1−λ)/M₂
```

Then `y ≥ 0`, **both** dual constraints hold with **equality**, and the dual objective is exactly
`(a² + 3a)/2` — Oler's own value. At `a = a_Oler(n) = (√(8n+1) − 3)/2` that is exactly `n − 1`,
so `B ≥ n` and the family cannot certify that `n` points fail to fit at that side length.

`a` is an irrational algebraic number, so nothing is rounded: the whole certificate is checked in
the exact quadratic field `Q(√(8n+1))` with `fractions.Fraction` coefficients. **No rounding step
and no repair step was needed** — the natural dual is exactly feasible.

## Discipline

- **No floating point appears anywhere in this directory at all**, not merely in the accept/reject
  decisions. Every comparison is between exact `Fraction`s or exact elements of a quadratic field;
  even the decimal display helper `dec()` is exact integer arithmetic, and `grep -n "float" *.py`
  matches only prose. STEP 5 compares exact rational predictions against digit strings transcribed
  from the sibling's report — it certifies nothing and is labelled as such.
- **The checker is validated before use.** `exact._selftest` solves a 2×2 LP whose optimum `7/5`
  is computed by hand, accepts the tight dual and a strictly interior one, and **rejects** three
  bad duals: one with a negative component, one violating `Aᵀy ≤ c`, and one infeasible by
  `1/1000`. It then repeats the exercise with `Q(√3)` coefficients.
- **Runtime** is a few seconds. No seeds, no network, no background jobs.

## Reproduce

```
cd experiments/packing-r4-dual && python3 certify.py
```

Python 3.11.15; stdlib only except `sympy` 1.14.0, used **only** in STEP 2 (the symbolic identity
check) and skipped with a printed notice if unavailable — STEP 1's certificates do not use it.
STEP 4 additionally reads `../packing-r4-delaunay/framework.py` and is skipped with a printed
notice if that import fails.

## What came out

- **Exact dual certificate: VERIFIED** at `n = 16, 17, 18`, twice each (tightest available
  bracket, and a lattice-only bracket that applies to the sibling's library from refinement
  size 5 onward). Both dual constraints tight, dual objective exactly `n − 1`.
- **Symbolic identity: VERIFIED.** The three dual relations hold identically in
  `(a, r₁, M₁, r₂, M₂)`, so the certificate is not fitted to these three `n`. Since the side-`m`
  lattice has slope `m`, every `a ≥ 1` is bracketed — the collapse holds at every `n`, not just
  16–18.
- **Collapse proposition: closes** (prose, `sketch`; stated in the attack README §2). Its
  arithmetic core, the Euler telescoping identity `(F + b)/2 = n − 1`, is verified exactly on all
  22 configurations.
- **Bridge: VERIFIED.** Against the sibling's *own* outward-rounded LP rows, the family's
  threshold in `d` exceeds `√(8n+1) − 3` by at most `2·10⁻²⁹ + 10⁻⁴⁰`.
- **Consistency: all six rows** of the sibling's published LP table are reproduced by the
  proposition, including the two that sit *above* Oler.

## What this does NOT show

It is a statement about the LP over **this formalisation of this family**. It does not say that no
localised-scoring bound can beat Oler. See the attack README §5 for the scope limits, stated in
full.
