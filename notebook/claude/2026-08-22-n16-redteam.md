## What I set out to do

Find the fifth instance of `FINDINGS.md`'s pattern: a correct theorem read one step too broadly.
Priorities as briefed: status graph, circularity, the separation-1/2 trap, the strictness/equality
case, over-claimed negatives, novelty.

## What happened, in order

**1. Re-derived the headline first, before reading any of the reasoning.** I hand-transcribed the
15 polygons out of `n16-covering-2/README.md`'s markdown table into my own `Q(sqrt3)` class and
ran containment / strict convexity / all 105 pairwise clippings / area identity / grid probe /
squared diameters. Everything passes; the max squared diameter is exactly 1 on **all fifteen**
pieces; areas sum to exactly `13 + 4 sqrt3 = a^2` in shoelace units. Afterwards I diffed my
transcription against `exact_1p2r3.py` — identical vertex-for-vertex, so the published table is
the object the code checks.

Doing it from the table rather than the JSON was the right call: it checks a thing nobody else
checked, which is that the *write-up* is the certificate.

**2. The equality case is fine, and I am fairly confident about that.** I expected this to be the
break. It is not. The distinction that makes it work is worth writing down because it is subtle
and it is exactly what broke Lemma L:

- FALSE: "covered by N sets of diameter <= 1 => at most N separated points" (witness: T_sqrt3,
  three kites of diameter exactly 1, four separated points).
- TRUE: "covered by N sets of diameter <= 1 => a_{N+1} >= a", by dilating by mu < 1.

The second does not need compactness at all — the feasible side-length set is upward closed, so
its infimum is >= a. And on the witness that kills the first, the second returns a_4 >= sqrt3,
which is exactly right. That is the check I would run first as a reviewer, and it is the check
the write-up itself nominates.

**3. The separation trap did not fire anywhere.** I checked all seven conversions in the campaign
at 40 digits plus the `n16-occupancy` capacity table (nine entries). All correct. Given
2026-08-21's broadcast error this was the highest-prior place for a break, and it is clean. Worth
reporting as loudly as a break would have been.

**4. Circularity is clean in the covering lanes, and guarded in the one lane where it is live.**
No `a_n` table exists in any covering experiment directory; `4.6247636` appears only as a
`CEILING` constant in tripwires and printouts. `n16-occupancy` is the lane that genuinely eats
`cited` a_k values, and its `CAP_MAX_INDEX_FOR(n) = n-1` guard is enforced at the table lookup,
so at n = 16 the biggest usable entry is a_14 = 4 against a whole triangle of 4.46 — no
whole-region prune, no path for the conclusion to re-enter.

**5. Then the actual findings, all in the sentences rather than the numbers.**

The two that matter:

- **"the layout is 3 corner + 9 edge + 3 interior" is not proved.** The counting yields
  n_2 >= 3, I <= n_2, n_1 + 2 n_2 >= 15 and nothing more. The step that excludes n_2 = 6 assumes
  a two-side piece cannot reach a side's middle. It can: the segment from (21/20, 0) on AB to
  (1/4, sqrt3/4) on AC has squared length 331/400, i.e. length 0.9097 < 1, touches both sides,
  and its endpoint on AB is 1.05 > 1 from A and 3.41 > 1 from B, so it is in M_AB. And n_2 in
  {4,5,7} is never considered at all — (n_1, n_2, I) = (7, 4, 4) survives every proved
  constraint. I *is* >= 1 (the incentre is 1.289 from every side), which kills 3/12/0 but nothing
  else.
- **"the family is exhausted"**, which is what tells the next worker to leave. Three `sketch`
  optimiser findings, none of which bounds the family. The campaign's own triage file forbade this
  inference four days earlier, verbatim: "*a search that fails to find an (n-1)-cell cover does
  not prove that none exists ... never 'm(16) ='*" (`approaches-round-2` §L). And its sibling
  lane `n16-shapes` §7.2 says the opposite on the same day.

`n16-verification-3` landed while I was writing this and reaches the *same* conclusion about the
forced structure by a *different* route — and its §7 explicitly certifies as "also correct" the
sub-step I break. Two Opus 5 passes, opposite verdicts on one sentence. My side has an exact
witness and a repair (the corner-containing pieces, not all two-side pieces, are what you count
out of the middles — which still yields n_int <= 3 unconditionally, so the useful half survives).
Per problem RULES.md §3.4, that disagreement is itself a finding and I have logged it as one
rather than assuming the later pass is right because it is later.

The prettiest one:

- **`n16-shapes` §5's Reuleaux row is false and its sibling lane already contains the refutation.**
  It claims a boundary piece covering a length-l chunk of a side has "no penalty" and can reach
  (pi - sqrt3)/2 = 0.7048, witnessed by a Reuleaux triangle "with its base on that side". A
  Reuleaux triangle's boundary contains no segment, so inside a half-plane it meets the boundary
  line in exactly one point — there is no base. The true cap at l = 1 is
  f(1) = pi/3 - sqrt3/4 = 0.6141848, *below* the hexagon figure, and `n16-covering-limit` §3
  computes it exactly and says explicitly that the extremal set is the two-arc lens and "not a
  Reuleaux triangle". Two lanes, same day, contradicting each other; the wrong one is the one
  that drives `n16-shapes`'s "where the money is" prioritisation.

  Nice confirmation: the standing certificate obeys f(1). Its three trace-1 edge pieces have area
  0.5669873 each; the 0.616 pieces all have trace sqrt3 - 1. So a bound derived in one lane by an
  LP/slice argument is satisfied exactly by a certificate built in another lane by an optimiser —
  a genuinely independent cross-check that nobody had run.

Plus an arithmetic slip in `n16-dual` (9.36499 gives a <= 4.6505482, not 4.65194 — they
effectively used 0.65 for 3 sqrt3/8), an over-strong "provably not tight" at m = 8 (it is an
optimiser plateau; A_8 <= 3 is proved, A_8 < 3 is not), a "(verified)" label in `n16-covering`'s
banner on a rational no certificate file supports, and a tripwire rounded the wrong way
(4.6247636 vs the true 4.6247635795).

**6. Repo-internal prior art nobody cited.** `approaches-round-2` §J (2026-08-18) already contains
the dilation/limit argument and "pigeonhole needs a cover, not a partition — overlap is harmless",
and §L already defines the target quantity. Four lanes rediscovered them and none cites the file.
Same shape as the Groemer entry in `FINDINGS.md`: an indexing failure, not a reading failure.

**7. Egress is more open than the campaign thinks.** Direct HTTPS and `WebFetch` are 403'd at the
gateway for every scholarly host I tried. **`WebSearch` is not.** It returned the sentence that
matters most for novelty: Melissen (1993) proved n = 4..12 "using only partitions and direct
applications of Dirichlet's pigeon-hole principle" — sourced to Tedeschi & Mackey, which this repo
has read *in full* and holds as `cited`. So the method is published and the repo already knew;
only the specific 15-piece value at n = 16 is genuinely unchecked. I updated the novelty framing
accordingly and listed the four PDFs that would settle it.

## What I would do differently

first would have been better: it took ten minutes, it is the only load-bearing object, and knowing
it was solid changed what I looked for afterwards (scope, not arithmetic).
