## What I reimplemented rather than reran

Explicit arc multiset, `set`/`dict` structures, `itertools` enumeration. The author's
`verify.py` uses bitmasks and closed-form counts, so agreement is not shared-code
agreement. `acz.py` on `main` served as a third implementation for cross-check; it
agrees on 271 M1 bases and on `tau = 3`.

Confirmed: 48 arcs with all source degrees 4 and sink degrees 3, `rho = 4`;
`tau = 3` checked over *every* `U` with `delta^-(U)` empty, not just the 4,094
source shores; exactly 32 M1 bases inside `{0..7}`, matching `target_bases`; the
family satisfies basis exchange with submodular rank 4, so it is a real matroid;
and it is not strongly base orderable — 24 of 496 pairs fail, with `(0237, 0456)`
showing exactly the five ID1009 exchange edges and Hall failing at `{2,7}`.

## The two things worth remembering

**The ground is a genuine `Q1 union Q2`.** `{0,...,7} = 0234 + 1567` with `89AB` the
third M1 basis, so this is the shape Question 8.1 is about, not an arbitrary
8-element restriction. I checked this because the PR did not, and it is what makes
the certificate ACZ-relevant rather than merely matroid-theoretic.

**The ACZ route is undamaged, and I quantified it.** All 1,146 partitions of the 12
active sources into three M1 bases satisfy the Question 8.1 condition; 219 of the
222 distinct two-base grounds are SBO. Even the partition containing the bad ground
passes via its other two pairs. So a non-SBO restriction existing at `rho = 4` says
nothing against the route — which is what the PR claimed, and now with numbers.

## Notes I raised (none blocking)

1. "Every ACZ M1 restriction is SBO" is already refuted at `rho = 3` by ACZ Figure 11
   — the repo's own D27 test asserts it. The new content is the `rho = 4` rank-4
   Hall obstruction; the README understates itself as a rediscovery.
2. "Unique minimum dicut" holds only among proper source shores: the 16 sets
   (all sources + 15 sinks) also cut 3. `tau` is unaffected; `verify.py`'s loop
   simply never reaches `X` = all sources, where `acz.py` handles it via
   `min(sink_degrees)`.
3. `output.json` hard-codes `missing_bases`, `extra_bases`, `four_subsets_checked`,
   `minimum_shores`. True only because the asserts force them — a certificate should
   not contain values that would survive a weakened assert.
4. `word(value, ground_size=8)` silently drops elements `>= 8`; harmless here, a
   landmine at `m = 12`.
5. No catalogue is committed, so `1009_8_4_32` is not checkable in-repo, and an ID
   names an isomorphism class while `target_bases` fixes a labelling. Non-blocking
   because the SBO refutation does not depend on the identification — I verified
   non-SBO directly from the base family.

not re-derive it from the primary source: arxiv.org and eprints.lse.ac.uk are both

`experiments/woodalls-rho4/README.md`, corroborated by the merged D27 fixture
reproducing ACZ's published Figure 11 claims. If that reading is wrong, everything
above verifies the wrong object. Whoever next gets the paper should close this.
