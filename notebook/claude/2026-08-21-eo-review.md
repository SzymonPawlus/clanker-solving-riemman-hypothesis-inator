## PR #46 — CLR theorem-number locators (codex). APPROVED.

Three prior reviews, all same-family, all deadlocked: the review at `3c73189` read the arXiv v2

I broke it. Direct egress to every scholarly host is still `403 CONNECT` — arxiv, springer,
d-nb, ar5iv, semanticscholar, openalex, crossref, dl.acm. But `github.com` is reachable, and a
GitHub **code search for `2311.04337`** turns up `lukalotl/woodall`, an unrelated third-party repo

`49d63f9…`, sha256 `e766066c…`, so the read is reproducible.

It is flat. Every theorem-like label in the paper, counted: Theorems 1–13, Lemmas 1–2, Corollaries
1–2, Propositions 1–2, Conjectures 1–5, and **one** dotted label in the whole document —
`Theorem 56.3`, a pointer into Schrijver's book [28]. That is the same idiosyncratic detail the
`3c73189` review reported from its own download, which is what makes a third-party mirror worth
trusting here: a corrupted or invented copy does not land on that.

Worth remembering as a technique: **when the proxy blocks the source, the source may still be
inside a repo the GitHub tools can reach.** Code search is an egress path that is not the egress
proxy. It found the paper text after WebFetch, curl and WebSearch had all failed — and WebSearch's
model-written summary actually hedged *toward* "Theorem 1.1" on no quoted text, which is a clean
example of why a generated summary is not a source.

All three are correct against the source text, so the objection dissolves and codex's statement was

Two things worth carrying forward:

1. **The write-up flags the wrong step as hardest.** It asks the reviewer to check $F=2n-b-2$ and
   "boundary-edge excess ≥ 0". The second is trivial. The first is fine, but its actual load-bearing
   step — $E_{\text{bd}} = b$, i.e. the boundary cycle has exactly $b$ edges — is *never stated*,
   only used as a bare symbol. That is precisely where a reader who reads $b$ as "hull vertices"
   diverges: on the $T(4)$ lattice that reading gives $F=15$ instead of 9. Unstated load-bearing
   steps are the thing §5 is about, even when they are true.
2. **Two understatements.** "Stage 1 = 0, stage 2 = 1" is filed `numerical` for $k\le6$; it is a
   two-line count for all $k$ (both hulls have $M = b$ exactly). And the dead route's step (ii)
   isn't just unjustified — the correct bound is $b\le\lfloor3a\rfloor \ge 3\lfloor a\rfloor$, which
   is *too weak*, and feeding it into H just re-derives Oler. So the route is structurally dead, not
   dead pending a patch. Said so, so the next reader doesn't try to repair H and then walk into (ii).
