## What I was sent to do

Find out cheaply whether the $\vartheta'$ route shares the ceiling that killed
`r3-sdpgate`. The framing I was given: sdpgate showed a level-2 moment relaxation whose
value saturates at $\sqrt6$ while $d(n) \sim \sqrt{8n}$, so it is asymptotically worthless;
does AC's $\vartheta'$ do the same? Gate: compute the $\vartheta'$-derived floor at known
$n$ and compare against Oler's $\sqrt{8n+1} - 3$.

## The move that made it cheap

I did not build the SOS problem. Instead:

> For finite $W \subset T_d$, a feasible kernel for $G_d$ restricts to a feasible matrix
> for $G_d[W]$, so $\vartheta'(G_d[W]) \le \vartheta'(G_d)$.

So a finite witness gives an **upper bound on the $\vartheta'$ floor** — against every
kernel of every degree, from one ordinary SDP. That is the cheapest possible refutation
device for this whole family, and it is worth remembering as a tool independent of this
attack.

It is strictly one-sided: it can show the method is too weak, never that it is strong.
I flagged that before running anything, which is why the null result below is a null result
rather than a claim.

## Three things I got wrong going in, corrected by doing it

1. **I expected the gate to fire.** Given sdpgate, "bounded and useless" was the stated
   prior. It did not fire anywhere. At $d$ well below $d(n)$ — every `oler-floor` row —
   $\vartheta'(G_d[W])$ came out *equal* to $\alpha(G_d[W])$ to a few thousandths; nearer the
   critical $d$ it exceeded $\alpha$, but never by more than about $0.45$, where firing the
   gate needs a full 1. So the relaxation is at or near exact on every finite witness I
   built.
2. **I expected an asymptotic saturation to be the punchline.** There is none.
   $\alpha(G_d) \le \vartheta'(G_d) \le \bar\chi(G_d)$ with both ends $\Theta(d^2)$ — I
   derived the upper end by an explicit clique-cover kernel plus a hexagon tiling rather
   than citing the sandwich. So $d_{\vartheta'}(n) = \Theta(\sqrt n)$: the right order. The
   sdpgate story does **not** generalise, and it would have been an easy and wrong
   inference to make.
3. **The assigned gate turned out to be mis-aimed.** "Does $\vartheta'$ beat Oler" has an
   a-priori answer *yes*: $\vartheta' \le \bar\chi$ means $\vartheta'$ inherits every
   diameter-cover floor, and the repo's covering plateau ($d(16) \ge 2+4\sqrt3 = 8.928$,
   `sketch`, unmerged, so I did not depend on it) is already above Oler's $8.358$. AC's
   dominance claim is simply correct.

## What actually kills AC's selling point

AC sells itself as "an SOS problem in $\sim4$ variables, **independent of $n$**". The rank
argument:

- images of an independent set under $\phi$ are pairwise obtuse, and $\mathbb{R}^r$ holds
  at most $r+1$ pairwise obtuse vectors, so $\operatorname{rank} Z \ge \alpha(G_d) - 1$;
- a kernel of degree $\le m$ per argument has rank $\le \binom{m+2}{2}$;
- so $\binom{m+2}{2} \ge \alpha - 1 \approx n$, i.e. $m \gtrsim \sqrt{2n}$.

Four variables for every $n$ — and degree growing like $\sqrt n$, so Putinar blocks like
$n^2/6$ and scalar variables like $n^4$. The invariant quantity is the wrong one. At
$n = 16$ the instance is nonetheless small (a $70\times70$ block and seven $\sim35\times35$),
which is why I recorded "just run it" as the reopening condition rather than closing the
door.

## Discipline notes to self

- The first ladder I ran used SCS at `eps = 1e-4` and showed $\vartheta'$ *growing* with
  grid refinement — 6.03, 6.21, 6.27. That was pure solver slop; at `eps = 1e-6` the same
  instance gave 6.001. **I nearly wrote up solver noise as a trend.** The fix was to stop
  reporting solver output at all and report a *repaired* primal instead: symmetrise, zero
  the edges, clip negative, shift by $tI$, rescale trace. That number is the objective at an
  exactly feasible point, so solver error can only weaken it. Every value in the write-up is
  that.
- Corollary of the repair: the refinement ladder's later rows have *lower* reported values,
  not because $\vartheta'$ falls but because the per-solve cap leaves the big instances
  unconverged. That is the instrument degrading, and I said so in the write-up rather than
  presenting a fake trend.
- Adjacency is decided symbolically ($a^2+ab+b^2$ versus $4(k-1)^2/d^2$), not by tolerance.
  My first version asserted "no near-ties" and immediately fired on $d = 2(k-1)$, where the
  grid spacing is exactly 2 — the tie is *real* and resolves to non-adjacent under the
  non-strict convention. Good bug: it was the convention checking itself.
- **The witness was mis-designed and I only caught it from an anomaly.** The corner-to-corner
  grid has spacing $d/(k-1)$, which for generic $d$ is incommensurate with the packing
  distance 2 — so it contains *no* pair at distance exactly 2, and its $\alpha$ undershoots
  the container's. It showed up as $\alpha = 10$ at $d = 7.99$ where the container holds 14.
  Fixed with a lattice-anchored grid of spacing exactly $2/r$; that also makes adjacency the
  pure integer test $a^2+ab+b^2 < r^2$. The self-tests passed *before* this bug and after,
  because they only probe $d = 2(k-1)$, where the two grids coincide. **Self-tests that only
  cover the commensurate case do not cover the case you actually run** — I have since added
  anchored-grid rows to the self-test, but they have the same blind spot, and I said so.
- `pkill -f pilot4.py` killed my own shell, because the pattern matched the wrapper command
  line. Use PIDs.
- **I ran the first battery twice by accident** — one launch appeared to fail (a shell exit
  code) but had in fact started, and I launched again. Both wrote to `results.json`, so it
  held 28 records of which 14 were duplicates, and every solve was competing for cores with
  its twin, which is why so many hit the per-solve cap. Deduped by keeping the better
  (larger, i.e. more informative) lower bound per configuration. The damage was only to
  convergence, not to validity — a repaired-primal lower bound is valid however badly the
  solver converged — but it is exactly the kind of thing that would silently corrupt a
  *tolerance*-based conclusion.
- **My worktree was deleted out from under me at 16:08, mid-run, with nothing committed.**
  `/home/user/r3-worktrees/theta` vanished (the manager was editing `FINDINGS.md` in the main
  repo at 16:07, so this was probably a round-3 worktree cleanup catching a round-4 branch
  living in the round-3 directory). The branch `r4-theta` survived because it is a branch;
  the *files* did not, because I had not committed once in ninety minutes. Recreated the
  worktree with `git worktree add` and rebuilt every file, then committed before doing
  anything else. **Commit first, compute second.** The rule in the protocol about
  checkpointing partial results to disk is not enough on its own — disk is not durable here;
  git is.

## Left on the table

- **The SOS solve at $n = 16$, $m = 4$.** The only thing that would produce a number. Not
  done. This is the honest headline gap.
- **A better $W$.** Grids may be the wrong finite witnesses. Circulant-shaped point sets
  (equally spaced points on a circle) have $\vartheta' > \alpha$ by a fractional amount —
  $C_5$ in my own self-test is the smallest example — so a ring-augmented $W$ might fire the
  gate where a grid cannot. Cheap, and the natural next attempt if anyone wants to kill AC
  rather than cost it out.
- **The exact-rounding question.** AC leans on Dostert–de Laat–Moustrou (arXiv:2001.00256).
  `WebFetch` is blocked; I have the abstract only and do not know whether their rounding
  survives a container with a boundary. Recorded as unverified, not assumed.
