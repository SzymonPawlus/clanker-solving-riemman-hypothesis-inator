## Kill criterion (written before any computation, repo `RULES.md` §6.2)

The attack is **exactification of the best-known n = 16 configuration**. I abandon the exact
(algebraic) route and fall back to a rigorous rational/interval upper-bound certificate if any
of the following holds:

1. **K1 — pipeline gate.** The high-precision refiner + contact-graph extractor + exactifier does
   not reproduce a *known* exact value on a control case (n = 8, closed form
   `2 + 2*sqrt(3) + 2*sqrt(33)/3`, and n = 15, `8 + 2*sqrt(3)`). If the machinery cannot recover a
   published answer it may not be trusted on an open one. Not negotiable.
2. **K2 — contact graph ambiguity.** The contact set is not separated by a clear gap at 40+ digits
   (i.e. there is a pair distance in, say, `[2 + 1e-30, 2 + 1e-6]`, neither plainly a contact nor
   plainly slack), so the algebraic system is a guess rather than a reading.
3. **K3 — elimination blow-up.** The exact elimination (Groebner/resultant) does not terminate
   within 20 minutes of CPU, or produces a polynomial whose degree/height I cannot certify.
4. **K4 — under/over-determination.** The contact graph does not pin the configuration (after
   removing rattlers and the 3 rigid-motion dof, #equations != #unknowns), so there is no isolated
   algebraic solution to exactify.

On any of K2–K4 I deliver instead a **rigorous rational certificate**: exact rational coordinates
with a provably feasible, slightly-inflated `d`, giving an honest (not tight) upper bound, plus a
rigorous interval enclosure of the true optimum of the contact system. On K1 I stop and report.

**§4 tripwire.** If an exact value comes out *below* the published d(16) = 0.216227269309782
(Graham–Lubachevsky), that is, in order of likelihood, a bug, a misread table, an infeasible
configuration, then a discovery. It gets reported as a candidate to the manager, never as a
result.

**Normalisation assertion.** Certificates use separation 2, point-triangle side `d`, and
`s = d + 2*sqrt(3)`; GL's `d(n)` is the min pairwise distance of n points in a *unit* triangle,
so `d = 2/m` and `s = 2/m + 2*sqrt(3)`. This is asserted in code, not just in prose.
